# State Machine & Hard Invariants

This document formalizes the operational lifecycle and non-negotiable invariants of the `agent-verification` skill.
Box-drawing characters below are decorative only: if a renderer or tool cannot parse them, follow the SKILL.md `TASK → CONTRACT → … → DECISION` sequence, which is authoritative.

---

## 1. Lifecycle State Machine

```text
                 ┌──────────────┐
                 │  TASK → OUTPUT │  (Unverified candidate + originating task)
                 └──────┬───────┘
                        ↓
              ┌───────────────────┐
              │ DEFINE CONTRACT   │  (Draft from TASK, bind to OUTPUT)
              └─────────┬─────────┘
                        ↓
              ┌───────────────────┐
              │ EXTRACT CLAIMS    │  (Deconstruct into testable units)
              └─────────┬─────────┘
                        ↓
              ┌───────────────────┐
              │ GENERATE TESTS    │  (Select failure-capable test families)
              └─────────┬─────────┘
                        ↓
              ┌───────────────────┐
               │ RUN TESTS (TEST)  │  (Execute against evidence / reality)
              └─────────┬─────────┘
                        ↓
                ┌───────────────┐
                │ FAILURES?     │
                └───┬───────┬───┘
                  NO│       │ YES
                    │       ↓
                    │  ┌──────────┐
                    │  │  REVISE  │  (Targeted repair of failing claim)
                    │  └────┬─────┘
                    │       ↓
                    │  ┌──────────┐
                    │  │RE-EXTRACT│  (Invalidate dependent tests)
                    │  └────┬─────┘
                    │       ↓
                    │  ┌──────────┐
                    │  │ RE-TEST  │  (Mandatory re-verification)
                    │  └────┬─────┘
                    │       │
                    └───┬───┘
                        ↓
              ┌───────────────────┐
               │ ATTACK (ATTACK)   │  (Counterexamples, boundary cases)
              └─────────┬─────────┘
                        ↓
              ┌───────────────────┐
               │ TEST-AUDIT (AUDIT)│  (Blind spots / mutations)
              └─────────┬─────────┘
                        ↓
              ┌───────────────────┐
               │ FINAL (DECISION)  │
              └───────┬───┬───┬───┘
                      ↓   ↓   ↓
                    PASS  PASS_WITH_LIMITATIONS  BLOCKED / FAIL
```

Every arrow above is also a user-visible event: the agent emits one short
progress update when it enters a stage, before doing the work inside it
(`INV-057`, `references/progress-protocol.md`). The trace is recorded in the
contract as `progress_trace[]` and must agree with the states it narrates
(`INV-058`).

## 2. Gate Decision Definitions

- **`PASS`**: All critical acceptance conditions pass; critical claims are supported; no unresolved contradictions; all required re-tests completed successfully. Requires every critical test in `PASS` with a recorded `observation` (`INV-018`), every critical claim `VERIFIED` (or disclosed `SUPPORTED` per SKILL §10), `verified_at_depth`/`depth_executed` agreement (`INV-019`), `checklist_closure: true` (all §4 boxes checked or `N/A` with reason, `INV-028`/`INV-032`), decisive `evidence_ids[]` cited for each critical claim (`INV-029`), an `audit_trail` consistent with the contract (`INV-030`), empty `blocked_reasons[]` with no unresolved critical failure (`INV-035`), revision attempts below policy cap (`INV-033`), test-family match on every critical AC (`INV-034`), a current `contract_version` (`INV-036`), a `risk_level` meeting the task-class depth floor (`INV-037`), reciprocal test links (`INV-038`), reciprocal assumption-evidence links (`INV-039`), no `VERIFIED` critical claim capped by a `CONDITIONAL`/`UNVERIFIED` assumption (`INV-040`), a `retest_status` derivable from `revisions[]` (`INV-041`), every `resolved` failure backed by a passing revision+re-test (`INV-042`), disclosed depth downgrades logged and surfaced (`INV-043`), substantive escalation entries (`INV-044`), non-vacuous criticality (`INV-045`), a continuous escalation chain (`INV-046`), enumerated degradations (`INV-047`), complete revision invalidation (`INV-048`), every `NOT CHECKED`/budget-deferred item able to change the conclusion surfaced in `disclosed_limitations[]` or forced conditional/`BLOCKED` (`INV-049`), a structured `final_verdict.decisive_evidence_ids[]` that is non-empty and resolvable (`INV-051`), structured (ref-bearing) `disclosed_limitations[]`/`blocked_reasons[]` entries (`INV-052`), bidirectional `AC.test_ids` ↔ `tests.target_ac_ids` links (`INV-053`), every `retest_completed` revision traceable through `retest_test_ids[]` to passing tests on its changed claims (`INV-054`), a coded `failures[]` entry for every critical `FAIL`/`INCONCLUSIVE` test (`INV-055`), and, at CRITICAL depth, `external_check_result`/`mutation_result` citing executed test ids rather than prose (`INV-056`), and a live `progress_trace[]` covering the executed depth's cadence (`INV-057`) whose entries resolve to this contract's ids/states and end in the emitted verdict (`INV-058`), a verdict card derived field-by-field (`INV-059`), a closed trace with no dangling `RUNNING` entry (`INV-060`), an honest `trace_status` (`INV-061`), a redacted, bounded trace (`INV-062`), a lifecycle-ordered trace (`INV-063`), stage-correct trace refs (`INV-064`), a complete trace (`INV-065`), a provenance-bearing card (`INV-066`), verbatim card counts (`INV-067`), a terminal test suite with no unrun check (`INV-068`), a canonical machine-readable card header (`INV-069`), a verdict label that matches its own limitation/blocker/failure arrays (`INV-070`), evidenced assumptions with referenceable `AS-XXX` disclosures (`INV-071`/`INV-072`), a directional escalation chain whose downgrades are traced (`INV-073`), an audited checklist record for the §4 gate (`INV-074`), declared family exceptions instead of assumed mappings (`INV-075`), field-level evidence freshness (`INV-076`), declared test ground truth (`INV-077`), recorded revision deltas (`INV-078`), independent evidence (`INV-079`), derived attempt counters (`INV-080`), a recorded depth-step set (`INV-081`), substantive justification fields (`INV-082`), recorded scopes (`INV-083`), agreeing declared facts (`INV-084`), a step record that matches the trace (`INV-085`), a recorded severity history with no `PASS` over an unresolved `MAJOR`/`CRITICAL` failure (`INV-086`), concrete falsifiers rather than placeholders (`INV-087`), and trace summaries that name what they narrate (`INV-088`).
- **`PASS_WITH_LIMITATIONS`**: Core requirements pass, but non-critical uncertainties or bounded assumptions remain and are explicitly disclosed to the user. Allowed only for bounded `SUPPORTED`/`PARTIALLY_SUPPORTED` gaps (`INV-013`); every limitation in `final_verdict.disclosed_limitations[]`; also requires `checklist_closure: true` (`INV-028`/`INV-032`), decisive `evidence_ids[]` cited for each critical claim (`INV-029`), an `audit_trail` consistent with the contract (`INV-030`), empty `blocked_reasons[]` (`INV-035`), revision attempts below policy cap (`INV-033`), a `risk_level` meeting the task-class depth floor (`INV-037`), reciprocal test links (`INV-038`), reciprocal assumption-evidence links (`INV-039`), no `VERIFIED` critical claim capped by a `CONDITIONAL`/`UNVERIFIED` assumption (`INV-040`), a `retest_status` derivable from `revisions[]` (`INV-041`), every `resolved` failure backed by a passing revision+re-test (`INV-042`), disclosed depth downgrades logged and surfaced (`INV-043`), substantive escalation entries (`INV-044`), non-vacuous criticality (`INV-045`), a continuous escalation chain (`INV-046`), every non-`VERIFIED` critical claim and failing/untested non-critical AC/test enumerated in `disclosed_limitations[]` (`INV-047`), complete revision invalidation (`INV-048`), every `NOT CHECKED`/budget-deferred item able to change the conclusion surfaced in `disclosed_limitations[]` or forced conditional/`BLOCKED` (`INV-049`), a structured `final_verdict.decisive_evidence_ids[]` that is non-empty and resolvable (`INV-051`), structured (ref-bearing) limitation entries for every disclosed degradation (`INV-052`), bidirectional `AC.test_ids` ↔ `tests.target_ac_ids` links (`INV-053`), every `retest_completed` revision traceable through `retest_test_ids[]` to passing tests on its changed claims (`INV-054`), a coded `failures[]` entry for every critical `FAIL`/`INCONCLUSIVE` test (`INV-055`), and, at CRITICAL depth, `external_check_result`/`mutation_result` citing executed test ids rather than prose (`INV-056`), and a live `progress_trace[]` covering the executed depth's cadence (`INV-057`) whose entries resolve to this contract's ids/states and end in the emitted verdict (`INV-058`), a verdict card derived field-by-field (`INV-059`), a closed trace with no dangling `RUNNING` entry (`INV-060`), an honest `trace_status` (`INV-061`), a redacted, bounded trace (`INV-062`), a lifecycle-ordered trace (`INV-063`), stage-correct trace refs (`INV-064`), a complete trace (`INV-065`), a provenance-bearing card (`INV-066`), verbatim card counts (`INV-067`), a terminal test suite with no unrun check (`INV-068`), a canonical machine-readable card header (`INV-069`), a verdict label that matches its own limitation/blocker/failure arrays (`INV-070`), evidenced assumptions with referenceable `AS-XXX` disclosures (`INV-071`/`INV-072`), a directional escalation chain whose downgrades are traced (`INV-073`), an audited checklist record for the §4 gate (`INV-074`), declared family exceptions instead of assumed mappings (`INV-075`), field-level evidence freshness (`INV-076`), declared test ground truth (`INV-077`), recorded revision deltas (`INV-078`), independent evidence (`INV-079`), derived attempt counters (`INV-080`), a recorded depth-step set (`INV-081`), substantive justification fields (`INV-082`), recorded scopes (`INV-083`), agreeing declared facts (`INV-084`), a step record that matches the trace (`INV-085`), a recorded severity history with no `PASS` over an unresolved `MAJOR`/`CRITICAL` failure (`INV-086`), concrete falsifiers rather than placeholders (`INV-087`), and trace summaries that name what they narrate (`INV-088`).
- **`BLOCKED`**: Critical verification is impossible due to missing access, unavailable tools, or private external reality. The label itself is gated (`INV-070`): `blocked_refs[]` MUST be non-empty, and no `PASS`/`PASS_WITH_LIMITATIONS` may carry a blocker. The agent states what was checked, what was not checked, and what evidence is required. Machine-enforced (`INV-050`): every `BLOCKED` MUST carry non-empty `final_verdict.blocked_reasons[]`, each entry naming the inaccessible claim/tool and the evidence needed — a `BLOCKED` with no named reason is `VF-06`. Structured-entry enforcement (`INV-052`): each entry MUST be an object with a resolvable `ref` + `blocked_on` + `evidence_required`; an empty array or free-text-only entry still fails. When the inaccessible unit is an assumption, the ref MUST be its `AS-XXX` id (`INV-072`) — naming a claim while the real blocker is an unverifiable assumption misstates the blocker (`VF-06`).
- **Failover rule:** if a `BLOCKED` reason is later cleared (access/tool/evidence restored), every claim that depended on it MUST re-enter `RE-EXTRACT → RE-TEST` before any `PASS`/`PASS_WITH_LIMITATIONS` (`INV-011`); a verdict issued on a cleared blocker without re-test is `VF-06`.
- **`FAIL`**: A critical constraint or acceptance condition fails, or repeated revisions fail to resolve the core contradiction. Output is rejected. The label itself is gated (`INV-070`): `failure_refs[]` (unresolved `failures[].id`) MUST be non-empty — a `FAIL` citing only resolved failures is mislabeled. Machine-enforced (`INV-050`): the verdict MUST cite the violated `AC-XXX`/failed `CL-XXX` and its `F-XXX` taxonomy code — a bare `FAIL` naming no failure is `VF-06`. The cited `F-XXX` MUST exist as a recorded `failures[]` entry (via `detected_by_test_id`/`target_claim_ids[]`), and at CRITICAL depth a `FAIL` that invalidates external/mutation attestations MUST restate them from test ids, not prose (`INV-055`/`INV-056`).
- **Termination rule:** After 2 consecutive failed re-tests on the same critical claim, stop revising and return `FAIL` (or `BLOCKED` if the blocker is missing evidence/access). Log each revision attempt in the contract `revisions[]` array.

## 3. Mandatory Invariants (The Non-Negotiables)

| ID | Invariant | Description |
|---|---|---|
| **INV-001** | `UNVERIFIED ≠ PASS` | An unexamined output or unverified claim can never be promoted to PASS. |
| **INV-002** | `INCONCLUSIVE ≠ PASS` | Inconclusive test results must not be converted into approval. |
| **INV-003** | `REVISION INVALIDATES TESTS` | Any change to a claim immediately invalidates all prior tests that depended on it. Re-test is mandatory. |
| **INV-004** | `EVIDENCE SCOPE MATCH` | Narrow evidence cannot justify a broad universal claim. Claim scope must match evidence scope, and both scopes must be recorded to be comparable (`INV-083`). |
| **INV-005** | `CONFIDENCE ≠ EVIDENCE` | Model fluency, confidence, or internal agreement does not constitute proof. |
| **INV-006** | `NO COUNTEREXAMPLE ≠ PROOF` | Failing to imagine a counterexample is not mathematical proof of correctness. |
| **INV-007** | `SELF-AGREEMENT IS NOT TEST` | A test that merely checks if the model agrees with its own previous thoughts is invalid; each critical test must declare its `ground_truth`, and `SELF_AGREEMENT`/`CANDIDATE_RESTATEMENT` are `VF-03` (`INV-077`). |
| **INV-008** | `TEST MUST BE FAILURE-CAPABLE`| A test that cannot theoretically fail given a wrong answer is not a verification test. |
| **INV-009** | `CRITICAL CLAIMS REQUIRE TESTS`| Any assertion capable of changing the user's action or conclusion must be covered by a test. |
| **INV-010** | `NEVER INVENT EVIDENCE` | If external tools, sources, or access are missing, report `BLOCKED`; never hallucinate verification. |
| **INV-011** | `NO OPEN REVISION LOOPS` | A contract with `retest_required: true` and `retest_completed: false` can never close as `PASS` or `PASS_WITH_LIMITATIONS`. Enforce `revision_policy` exhaustion. |
| **INV-012** | `MIXED CLAIMS GATE AS WEAK LINK` | In a mixed `VERIFIED` + `SUPPORTED`/`PARTIALLY_SUPPORTED` contract, the final verdict follows the weakest critical claim: any undisclosed or non-minor critical gap forces `PASS_WITH_LIMITATIONS` at best. |
| **INV-013** | `DISCLOSE-AND-DOWNGRADE SCOPE` | `PASS_WITH_LIMITATIONS` covers bounded `SUPPORTED`/`PARTIALLY_SUPPORTED` gaps only; `UNVERIFIED`/`CONTRADICTED` criticals and `INCONCLUSIVE` critical tests can never be disclosed away — they force `FAIL`/`BLOCKED`/re-test. |
| **INV-014** | `CRITICALITY IS EXPLICIT` | Gate-critical means `critical == true` on the contract object, never a bare `importance` label; dangling cross-ids are `VF-01`. |
| **INV-015** | `CRITICAL AC NEEDS A TEST` | A critical acceptance condition with zero linked critical tests is `VF-01` and blocks `PASS`. |
| **INV-016** | `DEPTH EQUALS RISK CLAIM` | `risk_level` MUST equal the depth actually executed; claiming a higher level without its mandatory checks (or hiding an escalation) is `VF-06`. |
| **INV-017** | `EVIDENCE LINKS ARE BIDIRECTIONAL` | `claims[].evidence_ids[]` and `evidence[].supports_claim_ids[]` MUST agree within the same scope; one-sided links are `EF-02`. |
| **INV-018** | `NO BARE PASS` | A critical `PASS` without a recorded `observation` is `VF-06`. |
| **INV-019** | `DEPTH IS ATTESTED` | `final_verdict.verified_at_depth` MUST equal `depth_executed`; every escalation MUST appear in `final_verdict.escalation_log[]` with from/to/trigger/added checks. A missing log entry is `VF-06`. |
| **INV-020** | `FAILURES ARE CODED` | Every failure carries a taxonomy `category` + `type`; unclassifiable failures block `PASS`; `CRITICAL` severity on gate-criticals forces `FAIL`/`BLOCKED`. |
| **INV-021** | `TESTS ARE FALSIFIABLE` | A critical test without a declared `falsifiability` input is `VF-02` and blocks `PASS`. |
| **INV-022** | `CONFLICTS BLOCK VERIFIED` | Contradictory critical outcomes on one claim forbid `VERIFIED` until a deciding re-test resolves them. |
| **INV-023** | `RE-EXTRACT BEFORE RE-TEST` | Post-mutation re-tests on stale claim ids are `VF-06`; follow `REVISE → RE-EXTRACT → RE-TEST`. |
| **INV-024** | `FAILURES NAME THEIR CATCHER` | A non-audit failure without `detected_by_test_id` is `VF-01`; suite defects (`VF-*`) must be caught by `TEST-AUDIT`. |
| **INV-025** | `REVISIONS LINK TO FAILURES` | A revision with a dangling `triggered_by_failure_id` or empty change set is `VF-06`. |
| **INV-026** | `REVISIONS ARE MONOTONIC` | A revision MUST NOT widen scope, drop a critical AC, or downgrade severity to reach `PASS`; doing so is `VF-07`. The claim is now checkable: each revision records its `scope_delta` (`INV-078`). |
| **INV-027** | `EVIDENCE IS FRESH` | (Enforced structurally by `evidence[].observed_in_run`, INV-076.) A critical `VERIFIED` needs current-run evidence/observations (same `contract_id`); stale cache alone verifies nothing — re-observe or downgrade to `SUPPORTED`. |
| **INV-028** | `CHECKLIST BOXES ARE GATE-BOUND` | Each Pre-Decision Checklist box (contract §4) is bound to the invariant(s) it cites and MUST be recorded in `final_verdict.checklist_results[]` (INV-074); an unchecked box blocks `PASS`/`PASS_WITH_LIMITATIONS` and sets `checklist_closure: false`, and `checklist_closure: true` without the record is an unproven claim. |
| **INV-029** | `VERDICTS CITE DECISIVE EVIDENCE` | A `PASS`/`PASS_WITH_LIMITATIONS` verdict MUST name the decisive `evidence_ids[]` carrying each critical claim; an uncited or out-of-scope verdict is `VF-07` and fails the gate. |
| **INV-030** | `AUDIT TRAIL MATCHES CONTRACT` | `final_verdict.audit_trail[]` fields MUST be drawn from and agree with the contract (`depth_executed`, `verified_at_depth`, critical `observation`s, `revisions[]`, `escalation_log[]`); a trail contradicting the contract is `VF-06` and blocks `PASS`. |
| **INV-031** | `DEPTH STEPS ARE EXECUTED` | The executed verification MUST satisfy every mandatory step of the claimed `depth_executed` (verification-depth.md); a shortfall (claimed depth, skipped required checks) is `VF-06` — re-run at depth or downgrade with disclosure. The executed step set is recorded in `depth_steps[]` (`INV-081`). |
| **INV-032** | `CHECKLIST BOXES DECLARE APPLICABILITY` | Each §4 checklist box is checked or marked `N/A` with a stated reason; an unchecked box without an `N/A` reason leaves `checklist_closure: false` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-033** | `REVISION ATTEMPTS ARE CAPPED` | `revisions[].attempt_number_for_claim` MUST stay below `revision_policy.max_consecutive_failed_retests_per_claim`; reaching the cap without a resolving re-test forces the `on_exhaustion` verdict — a PASS at/over cap is `VF-06`, and the counter is derived rather than declared (`INV-080`). |
| **INV-034** | `TEST FAMILY MATCHES ACCEPTANCE CONDITION` | Every critical AC must be covered by a linked critical test whose `type` matches the AC's (otherwise a declared `family_exceptions[]` entry, INV-075) `test_family` (or a documented mapping); a mismatched-family "coverage" is `VF-04` and blocks `PASS`. |
| **INV-035** | `NO OPEN BLOCKERS AT VERDICT` | `PASS`/`PASS_WITH_LIMITATIONS` require empty `final_verdict.blocked_reasons[]` and no unresolved critical `failures[]`; blockers may only be absent (never waived) — cleared blockers require the failover re-test loop first. |
| **INV-036** | `CONTRACT VERSION IS CURRENT` | A contract gated to `PASS` MUST declare the current `contract_version`; obsolete or unknown versions MUST be migrated (fields added, rules re-read) before the gate — gating a stale contract is `VF-06`. |
| **INV-037** | `DEPTH SELECTION HAS A FLOOR` | `risk_level` MUST satisfy the task class's depth trigger (verification-depth.md §1) with the tie-break (ambiguous → HIGHER); a self-consistent under-selected pair (`risk_level == depth_executed` below the floor) is `VF-04` — INV-016 consistency never waives the floor. |
| **INV-038** | `TEST LINKS ARE BIDIRECTIONAL` | `claims[].test_ids[]` and `tests[].target_claim_ids[]` MUST agree within the contract (mirrors INV-017 for tests); a one-sided test link is `VF-01` and blocks `PASS`. |
| **INV-039** | `ASSUMPTION EVIDENCE IS RECIPROCAL` | `assumptions[].evidence_ids[]` and `evidence[].supports_assumption_ids[]` MUST agree; an assumption citing evidence that does not reciprocate (or a dangling id) is `EF-02` and its dependents may not be gated `VERIFIED`. |
| **INV-040** | `ASSUMPTION STATUS CAPS DEPENDENT CLAIMS` | A critical claim depending on a `CONDITIONAL` or `UNVERIFIED` critical assumption MUST NOT close as `VERIFIED` — cap at `SUPPORTED` with the condition disclosed as an `AS-XXX` ref (`INV-072`); a capped claim gated `VERIFIED` is `VF-07`. |
| **INV-041** | `RETEST STATUS IS DERIVED` | `final_verdict.audit_trail.retest_status` MUST be derivable from `revisions[]` (`NOT_REQUIRED` only with no `retest_required`; `REQUIRED` while any is outstanding; `COMPLETED` only when every required re-test completed passing; `FAILED` on the exhaustion path); a contradicting status is `VF-06`. |
| **INV-042** | `FAILURE RESOLUTION IS EVIDENCED` | `failures[].resolved: true` requires a linked revision (`triggered_by_failure_id`) whose re-test completed with a passing result on the failure's `target_claim_ids[]`; flipping `resolved` without that pair is `VF-07`. |
| **INV-043** | `DEPTH DOWNGRADES ARE DISCLOSED` | An executed-depth downgrade below `risk_level` (or below the task-class floor, per INV-031's disclosed-downgrade path) MUST appear in `escalation_log[]` and in `disclosed_limitations[]`; an undisclosed downgrade is `VF-06`. |
| **INV-044** | `ESCALATION LOG IS SUBSTANTIVE` | Every `escalation_log[].added_checks[]` id MUST exist in `tests[]` and reference a test actually executed (terminal, not `PENDING`/`RUNNING`) at/after the escalation; logging intention instead of execution is `VF-06`. |
| **INV-045** | `CRITICALITY IS NOT VACUOUS` | The contract MUST declare >= 1 critical AC and >= 1 `critical: true` claim carrying the task's central conclusion; all-non-critical central claims make every critical gate vacuously true and are `VF-04`. |
| **INV-046** | `ESCALATION CHAIN IS CONTINUOUS` | `escalation_log[]` entries MUST chain (`from` = previous `to`; MINIMAL < STANDARD < ADVERSARIAL < CRITICAL; final `to` = `depth_executed` unless a disclosed INV-043 downgrade intervened); a broken or self-contradicting chain is `VF-06`. |
| **INV-047** | `DEGRADATIONS ARE ENUMERATED` | `PASS_WITH_LIMITATIONS` requires every non-`VERIFIED` critical claim and every failing/untested non-critical AC/test to be listed in `disclosed_limitations[]` — bounded means listed; an unnamed degradation is `VF-04` and blocks PSS_LIM. |
| **INV-048** | `REVISION INVALIDATION IS COMPLETE` | `revisions[].invalidated_test_ids[]` MUST include every test whose `target_claim_ids[]` intersect `changed_claim_ids[]`; a revision leaving a stale `PASS` test on a changed claim is `VF-06` and that result cannot support the verdict. |
| **INV-049** | `UNCHECKED ITEMS ARE SURFACED` | Every `NOT CHECKED` item (patterns §17) or budget-deferred check that could change the conclusion MUST appear in `final_verdict.disclosed_limitations[]` or force a conditional/`BLOCKED` verdict; silently dropped unchecked items are `VF-04` and block `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-050** | `REJECTION IS CITED` | A `FAIL` MUST cite the violated `AC-XXX`/failed `CL-XXX` + its `F-XXX` taxonomy code, and a `BLOCKED` MUST name the inaccessible claim/tool per `blocked_reasons[]` entry; a bare `FAIL` or reasonless `BLOCKED` is `VF-06` — every verdict carries justification, not only `PASS`. |
| **INV-051** | `VERDICT CITATION IS A FIELD` | `PASS`/`PASS_WITH_LIMITATIONS` MUST record decisive evidence in `final_verdict.decisive_evidence_ids[]` — non-empty, every id resolving to an `evidence[]` item that supports a critical claim of this contract; prose-only citation or an empty/dangling array is an ungrounded verdict and is `VF-07`. |
| **INV-052** | `VERDICT ENTRIES ARE STRUCTURED` | Every `disclosed_limitations[]` and `blocked_reasons[]` entry MUST be an object carrying a resolvable `ref` (CL-XXX/AC-XXX/TEST-XXX/tool) plus `kind`/`detail` (limitations) or `blocked_on`/`evidence_required` (blockers); a bare string or unresolvable ref counts as undisclosed (`VF-04`) or unstated (`VF-06`) — INV-047/049/050 inspect entries, not prose. |
| **INV-053** | `AC TEST LINKS ARE BIDIRECTIONAL` | `acceptance_conditions[].test_ids[]` and `tests[].target_ac_ids[]` MUST agree in both directions; a critical AC with zero linked critical tests, a one-sided link, or links failing the AC's `test_family` match is `VF-01`/`VF-04` — the AC-level mirror of INV-034/INV-038. |
| **INV-054** | `REVISION RE-TEST IS TRACED` | `revisions[].retest_completed: true` MUST be traceable through `retest_test_ids[]` to executed tests that target the revision's `changed_claim_ids[]` and ended in a passing terminal state; untraced or off-claim completion is `VF-07` and cannot satisfy INV-041/INV-042. |
| **INV-055** | `CRITICAL FAILURES ARE RECORDED` | Every critical test in `FAIL` or `INCONCLUSIVE` MUST have a matching `failures[]` entry (via `detected_by_test_id` or `target_claim_ids[]` overlap) with a taxonomy `F-XXX` code; an unrecorded failing critical test makes INV-035 vacuously true — the empty `failures[]` list is not health, and a verdict over it is `VF-06`. |
| **INV-056** | `CRITICAL ATTESTATION CITES ARTIFACTS` | At CRITICAL depth, `audit_trail.external_check_result`/`mutation_result` MUST cite ids of executed `tests[]` (external/mutation type, terminal) plus their observations; prose-only attestation with no linked executed test is `VF-06` and blocks `PASS` — binds INV-031's claimed steps to artifacts. |
| **INV-057** | `PROGRESS IS STREAMED, NOT RETROFITTED` | At every depth, the agent MUST emit the opening progress update before the first verification action and one update per lifecycle transition before starting the next stage (depth, contract, claims, tests, each failure/revision/re-test, escalation, decision); the contract `progress_trace[]` records them with `emitted: LIVE`. A silent run whose trace appears only at verdict time is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`; a runtime unable to stream MUST record `emitted: RETRO` plus a `TRACE_DEFERRED` limitation — never fake live delivery. |
| **INV-058** | `TRACE IS GROUNDED IN THE CONTRACT` | Every `progress_trace[]` entry MUST resolve to contract ids/states: `refs` exist, `stage` is a defined stage, `status` agrees with the referenced test/revision state, `summary` asserts no check or result missing from `tests[]`, and the final `DECISION` entry states the same verdict as `final_verdict.status`. Invented checks, dangling refs, a trace omitting a recorded revision/escalation, or a verdict card contradicting the contract are `VF-06`/`VF-09`. |
| **INV-059** | `VERDICT CARD IS DERIVED` | Every verdict carries `final_verdict.verdict_card`; `verdict` equals `final_verdict.status`, `critical_claims_total`/`critical_claims_verified` match `claims[]`, `tests_total`/`tests_passed` match terminal `tests[]`, `revisions` matches `revisions[]`, `decisive_evidence_ids` matches the verdict field, `limitation_refs` matches `disclosed_limitations[].ref` in order, `blocked_refs` matches `blocked_reasons[].ref`, and `failure_refs` matches unresolved `failures[].id`. The rendered card states the verdict, both ratios, and every limitation ref. A missing card, a hand-typed count, or a hidden limitation is `VF-10` and blocks `PASS`/`PASS_WITH_LIMITATIONS`; a `PASS` with non-empty `limitation_refs` is mislabeled and must be `PASS_WITH_LIMITATIONS`; the `rendered` card must contain the verdict and every `limitation_ref`/`blocked_ref`/`failure_ref`, and a rendered card that drops one is `VF-10` even when the fields match; `rendered` opens with the canonical header `<marker> <verdict> · <depth> · <trace_status>`, where the marker maps `✅/⚠️/⛔/❌` to `PASS/PASS_WITH_LIMITATIONS/BLOCKED/FAIL`, and carries exactly one whole-token verdict on that header line. |
| **INV-060** | `TRACE LIFECYCLE IS CLOSED` | `progress_trace[].seq` is contiguous from 1; no entry remains `RUNNING` at verdict time; every `RUNNING` entry reaches a terminal status (updated in place or followed by a terminal entry for the same stage); there is exactly one `DEPTH` entry (the first) and exactly one `DECISION` entry (the last, with a terminal status). A dangling `RUNNING`, non-contiguous sequence, or missing/early `DECISION` is `VF-09` and blocks every verdict, not only `PASS`. |
| **INV-061** | `DEFERRED TRACE IS HONEST` | `TRACE_DEFERRED` appears only when every `progress_trace[]` entry is `emitted: RETRO`, `audit_trail.trace_status` is `RETRO`, and the limitation names the runtime constraint in `ref`/`detail`. Any `LIVE` entry in the same run makes `trace_status` `MIXED` — capability proven once cannot be denied later — which is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`; a deferral without a named runtime constraint is an unevidenced excuse and fails the same gate; an all-RETRO trace with no `TRACE_DEFERRED` limitation is an undisclosed retro trace and is `VF-09` as well. |
| **INV-062** | `TRACE IS REDACTED AND BOUNDED` | `progress_trace[].summary`, the verdict card, and user-facing progress messages MUST NOT contain credentials, API keys, tokens, session identifiers, or personal data; cite `evidence[]` ids or paths instead. Each summary is non-empty and <= 280 characters; base entry counts stay within the depth cap (MINIMAL 3, STANDARD 12, ADVERSARIAL 14, CRITICAL 16), excluding one entry per recorded conditional event. A leaked secret is `VF-09`, requires immediate redaction and disclosure; an overlong or over-budget trace is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-063** | `TRACE ORDER FOLLOWS LIFECYCLE` | `progress_trace[]` stages respect prerequisite order: DEPTH before CONTRACT/CLAIMS/TESTS; CONTRACT before CLAIMS; CLAIMS before TESTS; TESTS before TEST/FAILURE; FAILURE before REVISION; REVISION before RETEST; the repair loop before ATTACK; ATTACK before AUDIT; AUDIT/ATTACK before EXTERNAL/MUTATION; DECISION last; ESCALATION at the point of the depth change. Narration that reports a later stage before its prerequisite is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-064** | `TRACE REFS MATCH STAGE ARTIFACTS` | Each `progress_trace[]` entry cites the artifact it narrates: CONTRACT → ≥1 `AC-*`; CLAIMS → ≥1 `CL-*`; TESTS/TEST → ≥1 `TEST-*`; ATTACK/AUDIT → ≥1 `TEST-*` or `CL-*`; FAILURE → `F-*`; REVISION → its `REV-*`; RETEST → executed `TEST-*` ids; ESCALATION → its `added_checks` `TEST-*` ids; EXTERNAL → an `external`-type test (or a `blocked_reasons[]` ref when the stage is `BLOCKED`); MUTATION → a `mutation`-type test (or the same blocked ref); DECISION → the decisive `EV-*` ids for PASS/PSS. Generic or wrong-kind refs are `VF-09` and block `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-065** | `TRACE IS COMPLETE` | Before `PASS`/`PASS_WITH_LIMITATIONS`, `progress_trace[]` opens with `DEPTH` at `seq: 1`; contains the required stage set for `depth_executed` (MINIMAL: DEPTH/DECISION; STANDARD: DEPTH/CONTRACT/CLAIMS/TESTS/TEST/ATTACK/DECISION; ADVERSARIAL adds AUDIT; CRITICAL adds EXTERNAL/MUTATION); and covers every artifact — each failure id appears in a FAILURE entry, each revision in a REVISION entry plus a RETEST entry covering its `retest_test_ids` when a re-test ran, and ESCALATION refs cover every `added_checks` id. A missing stage or artifact is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-066** | `CARD DECLARES PROVENANCE` | `verdict_card.depth_executed` equals `audit_trail.depth_executed`/`verified_at_depth`; `verdict_card.trace_status` equals `audit_trail.trace_status`; and the rendered card shows both tokens. A card that hides the depth or whether the trace was LIVE/RETRO/MIXED is `VF-10` and cannot represent the verification it summarizes. |
| **INV-067** | `CARD COUNTS ARE VERBATIM` | `verdict_card.rendered_counts` equals the formatted fields (`claims` = verified/total, `tests` = passed/total, `revisions` = count), and `rendered` contains the canonical footer `[claims=<claims>, tests=<tests>, rev=<revisions>]` exactly once as its last line. A missing, duplicated, non-final, or different footer, or prose stating a conflicting claims/tests pair, is `VF-10` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-068** | `NO DEFINED TEST IS LEFT UNRUN` | At verdict time no `tests[]` entry may be `PENDING` or `RUNNING`; every test is `PASS`, `FAIL`, `INCONCLUSIVE`, or `INVALIDATED`, and an `INVALIDATED` test must be named by a revision's `invalidated_test_ids[]` with a replacement re-test on the changed claims (INV-048/INV-054). `tests_total` counts only `PASS`/`FAIL`/`INCONCLUSIVE`. An unrun test silently shrinks the denominator, so the verdict is `VF-06` and cannot be gated. |
| **INV-069** | `CARD HEADER IS CANONICAL` | `rendered` is header + non-empty body + footer (last line). The header is exactly `<marker> <VERDICT> · <DEPTH> · <TRACE_STATUS>`; markers map `✅→PASS`, `⚠️→PASS_WITH_LIMITATIONS`, `⛔→BLOCKED`, `❌→FAIL`; verdict/depth/trace equal the card fields and exactly one whole-token verdict appears on the header line. Missing/mistranslated markers, a second header line, or a non-final footer is `VF-10` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-070** | `VERDICT LABEL MATCHES EVIDENCE` | `PASS` requires empty `limitation_refs`/`blocked_refs`/`failure_refs`; `PASS_WITH_LIMITATIONS` requires non-empty `limitation_refs` and empty `blocked_refs`; `BLOCKED` requires non-empty `blocked_refs`; `FAIL` requires non-empty `failure_refs`. A mismatch is a mislabeled verdict (`VF-10`): relabel it or close the gap, never reword the card. |
| **INV-071** | `ASSUMPTION VERIFICATION IS EVIDENCED` | `assumptions[].status: VERIFIED` requires >= 1 reciprocated `evidence_ids[]` entry (INV-039) whose `scope` covers the assumption; a critical assumption additionally requires an `EXTERNAL_TOOL`/`PRIMARY_DOC` source or a recorded observation. An unevidenced `VERIFIED` flip is `EF-01` and cannot lift a dependent critical claim toward `VERIFIED` (`VF-07`) — the status is a claim, not a permission flag. |
| **INV-072** | `CRITICAL ASSUMPTIONS ARE REFERENCEABLE` | `AS-XXX` is a legal `ref` in `disclosed_limitations[]` and `blocked_reasons[]`. Every critical assumption left `CONDITIONAL`/`UNVERIFIED` at verdict MUST appear in `disclosed_limitations[]` (its `AS-XXX` ref) or in `blocked_reasons[]` when the check cannot be obtained; a condition that lives only in prose is undisclosed (`VF-04`/`VF-06`) and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-073** | `ESCALATION IS DIRECTIONAL` | Every `escalation_log[]` entry carries an `ESC-XXX` id and a `direction`. `UP` requires a non-empty `added_checks[]` of executed tests and an empty `dropped_checks[]`; `DOWN` (disclosed downgrade) requires `dropped_checks[]` plus a `DOWNGRADE` limitation whose `ref` is its id. The chain ascends on `UP` and descends only on `DOWN`, ending at `depth_executed`; the ESCALATION trace stage for a `DOWN` cites that `ESC-*`. A wrong direction or unreferenced downgrade is `VF-06`. |
| **INV-074** | `CHECKLIST IS A RECORD` | `final_verdict.checklist_results[]` lists every §4 box exactly once under the parenthetical printed at the end of the box (its invariant binding or named rule) with `status: CHECKED | NA`; `NA` needs a non-empty `reason`. `checklist_closure: true` is valid only over that record; a missing/duplicate box, an `NA` without reason, or a `CHECKED` box whose cited gate fails is `VF-06` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-075** | `FAMILY EXCEPTIONS ARE DECLARED` | When a linked critical test's `type` differs from the critical AC's `test_family`, the AC MUST carry a `family_exceptions[]` entry naming the `test_id`/`test_type` with a non-empty `why`, and the test's `purpose`/`falsifiability` must name the same boundary. A silent mismatch is `VF-04` and blocks `PASS` — "documented mapping" means a record here, not an assumption that one exists. |
| **INV-076** | `EVIDENCE FRESHNESS IS A FIELD` | Every `evidence[]` item records `observed_in_run`; a critical claim closes `VERIFIED` only with >= 1 supporting item whose `observed_in_run` equals this `contract_id`, or a recorded observation from an executed test of this run. Prior-run evidence caps the claim at `SUPPORTED` with disclosure; a `VERIFIED` claim on prior-run evidence alone is `EF-03` and blocks `PASS`/`PASS_WITH_LIMITATIONS` (INV-027 as a field). |
| **INV-077** | `TEST GROUND TRUTH IS DECLARED` | Every critical `tests[]` entry declares `ground_truth` (`kind` + `ref`). `SELF_AGREEMENT` (compares the output with its own premises) and `CANDIDATE_RESTATEMENT` (re-verifies a rephrasing of the same claim) are `VF-03` and can never carry a critical `PASS`; `DERIVATION` names its premises and cannot be the sole support of a critical `PASS` at ADVERSARIAL+. An undeclared or self-referential ground truth blocks `PASS` — INV-007 as a field. |
| **INV-078** | `REVISION DELTA IS RECORDED` | Every revision records `scope_delta` (`dropped_ac_ids`, `dropped_claim_ids`, `narrowed_claim_ids`, `added_claim_ids`, `severity_changes`). Dropping a critical AC/claim or downgrading the triggering failure's severity is monotonicity-breaking `VF-07` and cannot reach `PASS`; affected units are disclosed in `disclosed_limitations[]` and re-gated — INV-026 as a field. |
| **INV-079** | `EVIDENCE IS INDEPENDENT` | Every `evidence[]` item records `origin` (`EXTERNAL_SOURCE | RUNTIME_OBSERVATION | CANDIDATE_OUTPUT | MODEL_RECALL`). A critical claim closes `VERIFIED` only with >= 1 `EXTERNAL_SOURCE`/`RUNTIME_OBSERVATION` item not derived from the candidate output; output-derived or recalled evidence caps the claim at `SUPPORTED` with disclosure, and a citation chain resolving back to the output is `EF-06` and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-080** | `ATTEMPT COUNTER IS DERIVED` | `attempt_number_for_claim` equals 1 + the earlier revisions (contract order) that changed the same claim since its last passing re-test, and never decreases for a claim. A lower, repeated, or reset counter is a cap escape (`VF-06`); a `PASS` that survives only because the counter was reset is `VF-07`. |
| **INV-081** | `DEPTH STEPS ARE RECORDED` | `final_verdict.depth_steps[]` records every numbered step of `depth_executed` (verification-depth.md §1) exactly once as `<DEPTH>-<n>` with `DONE` (+ resolving `trace_refs`/`artifact_refs`) or `NA` (+ non-empty reason, conditional steps only, forcing the INV-031 downgrade path). A missing/duplicate step or a ref-less `DONE` is `VF-06` and blocks every verdict. |
| **INV-082** | `JUSTIFICATION IS SUBSTANTIVE` | Limitation `detail`, blocker `blocked_on`/`evidence_required`, `NA` reasons, and family `why` must name the unit and the reason; placeholders (`N/A`, `-`, `none`, `TBD`) or restatements are not justification, and cited refs must resolve. Empty justification is `VF-06` (blockers/checklist/steps) or `VF-04` (limitations) and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-083** | `SCOPES ARE RECORDED` | The task `scope`, every `claims[].scope`, and every `evidence[].scope` are non-empty and substantive (they name the boundary: version, inputs, environment, population) — never a placeholder or a universal phrase like "all". An empty scope makes the INV-004 match vacuous (`EF-04`/`VF-04`) and blocks `PASS`/`PASS_WITH_LIMITATIONS`. |
| **INV-084** | `DECLARED FACTS AGREE` | `evidence[].source_type` and `evidence[].origin` must agree with the mapping table (EXTERNAL_TOOL→EXTERNAL_SOURCE/RUNTIME_OBSERVATION; PRIMARY_DOC/SECONDARY_SOURCE→EXTERNAL_SOURCE; LOCAL_STATE→RUNTIME_OBSERVATION/CANDIDATE_OUTPUT; MODEL_RECALL→MODEL_RECALL), and `tests[].type` must agree with `ground_truth.kind` (`external`→external/primary/runtime; `mutation`→external tool/runtime; `evidence`→a source kind). A contradiction is `VF-06`. |
| **INV-085** | `STEP RECORD MATCHES THE TRACE` | Every `depth_steps[]` DONE entry cites >= 1 terminal `progress_trace[]` seq, and the union of cited seqs covers every stage INV-065 requires for `depth_executed`. A step set citing only the DECISION entry, DONE refs that are all RETRO while the card says LIVE, or a required stage no step accounts for is `VF-06`/`VF-09` and blocks every verdict. |
| **INV-086** | `SEVERITY CHANGES ARE RECORDED` | Every `failures[].severity` change appears in the `scope_delta.severity_changes[]` of the revision that made it (`failure_id`, `from` = previous severity, `to` = current field, substantive `why`); a downgrade needs >= 1 resolving, current-run `evidence_refs` item. An unrecorded change or a downgrade with no new observation is `VF-06`; a downgrade of the triggering failure carrying a `PASS` is `VF-07`; no `PASS` may be issued over an unresolved `MAJOR`/`CRITICAL` failure (`MAJOR` caps the verdict at `PASS_WITH_LIMITATIONS`, `CRITICAL` forces `FAIL`/`BLOCKED`) — severity is a record and a floor, not a dial. |
| **INV-087** | `FALSIFIERS ARE CONCRETE` | A critical `tests[].falsifiability` names the wrong input/condition and the result the test would then show; it is not a placeholder, a restatement of `purpose`/claim `text`/the test's `observation`, or a falsifier already declared by another critical test on the same claim. A generic, restated, or duplicated falsifier is `VF-02` and blocks `PASS`. |
| **INV-088** | `TRACE SUMMARIES SAY SOMETHING` | Every `progress_trace[].summary` names the unit it narrates — an id from its own `refs`, or the concrete subject that ref names when the entry narrates a decision such as `DEPTH` — and states what was found or decided. A placeholder, a stage name alone, or a summary duplicated from another entry is `VF-09` and blocks `PASS`/`PASS_WITH_LIMITATIONS`: resolved refs are not narration. |
