## Experiment: E-033 — The trace has no entry cap

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** The progress protocol caps base trace entries per depth (MINIMAL 3, STANDARD 12, ADVERSARIAL 14, CRITICAL 16), with the mandatory DEPTH announcement and one entry per recorded failure/revision/retest/escalation outside the base budget — "exceeding the base cap means the updates became a log, not a trace" (`INV-062`). The gate measures summary length and secrets but never counts entries, so a contract can narrate every micro-step and still PASS.
- **Hypothesis:** H-033: "defect_rate >= 0.5"
- **Measurement Metrics:** defect_rate >= 0.5 — proportion of five trace-cap probes still admitted (unitless)
- **Experiment Design:** `scripts/bench/bench_optimization.py --suite tracecap` adds five probes: one and two extra MINIMAL entries, a FAILURE-labelled entry with no recorded failure (the exemption must come from the contract, not the stage label), a STANDARD run with 14 entries, and a prompt probe for the missing cap rule. The fifteen earlier suites stay unchanged. `--control clean` must fail the claim.
