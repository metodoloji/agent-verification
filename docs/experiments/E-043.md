## Experiment: E-043 — Version compatibility is unenforced and one gate is mislabeled

- **Date:** 02.11.2026
- **Status:** completed
- **Theory:** The spec defines `INV-036` as version compatibility: a contract gated to PASS must declare the current `contract_version` and carry a `contract_changelog[]` entry for that version; an unmigrated contract is `VF-06`. The gate never reads `contract_version` or `contract_changelog`, so a stale or invented version reaches PASS. During this round the invariant inventory also showed a labeling defect introduced in E-035: the claim-closure check was tagged `INV-036`, but that rule belongs to `INV-009` (a critical claim has a linked critical test), and the tag collided with the real version rule. The behavior stays; the id is corrected, and the real `INV-036` is implemented.
- **Hypothesis:** H-043: "defect_rate >= 0.5"
- **Measurement Metrics:** defect_rate >= 0.5 — proportion of four version-compatibility probes still admitted (unitless)
- **Experiment Design:** `scripts/bench/bench_optimization.py --suite version` adds four probes: contract_version 1.9, an unknown 99.0 that also self-approves in its changelog, a 2.0 contract whose changelog has no 2.0 entry, and a prompt probe for the missing version rule. The twenty earlier suites stay unchanged. `--control clean` must fail the claim.
